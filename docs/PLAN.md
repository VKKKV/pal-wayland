# PAL DOS 静态本机移植：固定要求

本文件定义目标与验收契约，不记录逐阶段进度。当前差距在
[功能账本](functionality.md)，操作入口在 [开发文档](development.md)。

## 原版身份与架构

- 输入是实际取得并记录身份的原版 DOS MZ；原 EXE、数据、音轨与已有存档保持不变。
  来源及固定哈希保留在 [资源 manifest](resource-manifest.json)、[CD manifest](cd-audio-manifest.json)。
- 构建时解码、恢复有限控制流并生成 Rust；运行时执行提前生成的指令语义与
  显式 DOS/BIOS/设备服务，保留分段地址、寄存器、FLAGS、内存及原脚本 VM。
- 运行时无 x86 fetch/decode、CPU interpreter、JIT、DOSBox fallback 或调用 DOSBox 执行。
  未知目标、服务或未经许可的代码变化必须明确失败，不关闭代码 guards 掩盖缺口。
- 重叠入口、原程序自修改和复制驱动只能采用已证明的静态 roots、有限 guarded views
  或窄 mutable-immediate 槽；观察到的新目标只能进入后续构建。
- 项目语言选择为 Rust。平台依赖按实际兼容性、许可与维护需要选择；采用现代
  SDLPAL 等实现研究格式、设备机制和设计 fixture，不以其算法替换原二进制逻辑，
  也不把其行为视为原版精确 oracle。引用/移植代码须满足其许可。

## 功能交付

- 提供持久、可重建的本机 ELF 与简短玩家入口；零参数启动实际游戏，不仅打印 help。
  资源不依赖 cwd，存档持久且与只读资源分离，首次配置不覆盖已有用户设置。
- 标题、新游戏、移动、对话、场景/剧情/物品、已知战斗代码、存档/重启读取、
  窗口/键盘、音乐及数字音效均在功能范围内；不能以仅有菜单或单段演示替代交付。
- 原游戏正常输入/加载/保存/设备调用驱动功能，不以写剧情 flags、注入物品、
  修改配置字节、强制播放资源或伪造设备结果制造通过。
- 目标是功能完整，而非完整通关、每一剧情/音轨/存档点覆盖或穷尽全状态差分。
  已有功能“未全面测试”和确认的缺失/阻断分别列出，不将覆盖不足自动当成缺失。
- 每次交付核对最终入口与构建身份，做短时代表性检查；语义/服务/安全缺陷追加
  有针对性的回归。窗口键盘、PCM 传输、源样本身份和可听声音是不同验收层。
  真实桌面/音频设备测试须有相应授权，自动回归默认 headless/静音/隔离。

## 安全与版权

- 合法取得资源用于本地分析，不把公开下载可得当作再分发许可。
- 原资源只读；写入仅在明确独立的 COW/用户 saves 下，拒绝目录重叠和不安全路径。
  保留已有用户设置和存档，不为验证成功回滚无关更改。
- 测试应使用原创、无版权资源 fixture；真实资源测试显式 opt-in，缺资源时明确失败。
- 原资源、资源派生代码、ELF、WAV、截图、RAM dump 与存档不提交/公开分发。
  开源工具许可证与第三方完整 notice 单独保留。
